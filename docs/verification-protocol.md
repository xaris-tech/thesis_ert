# Device verification protocol

How to demonstrate the device detects a known anomaly, and what each number is allowed
to claim. Written so it is repeatable by someone who was not present.

## The one rule

**No score is reported without its own empty-tank control.** Every run stores
`control_values`: the baseline differenced against itself, which by construction contains
nothing but noise. Score the detection and the control identically and report the
*margin*, not the raw score.

This is not ceremony. Before the region fix, an empty tank scored **0.90–0.96** on SSIM
while every real run scored 0.28–0.59 — a validation protocol without a null would have
declared the device working (ADR-0045 → ADR-0047).

## The three metrics, and what each may claim

Named per `CONTEXT.md`, which judges this system on "repeatable acquisition and
approximate conductivity-variation localization" (CONTEXT.md:8).

| metric | question it answers | may claim | may **not** claim |
|---|---|---|---|
| **Angular localization error** | where is the anomaly | localization, against photographic ground truth | anything about amplitude |
| **NCC** | does the image resemble the expected response | reproducibility of the reconstruction | correctness — the template comes from the same solver |
| **Dice** | what fraction of the claimed lobe is where the lobe is | extent of the recovered region | correctness, for the same reason |

The asymmetry matters. **Only the angle has ground truth that did not come from this
code.** NCC and Dice compare a reconstruction against a template generated by the same
solver, so a systematic pipeline bias moves both together and cancels. They demonstrate
the pipeline is self-consistent and repeatable — which is a real and necessary claim, but
not the same as being right.

### Naming

- **Angular localization error** (degrees) — `centroid_angle_error_deg` in code. Not
  "SSIM-like", not "angle accuracy". CONTEXT.md uses *localization*.
- Report in **degrees, never percent**. A percentage needs a denominator, and the
  defensible one — the 30° electrode spacing — makes "10%" mean 3.0°, which half the
  placements would fail. Percent is for ratios (reciprocity), per the existing convention.
- **NCC** is not SSIM. It measures linear agreement of an intensity pattern; two blobs of
  different size sharing a bright centre correlate highly. It is scale-invariant and
  position-sensitive.
- **Dice** depends on a stated threshold (`DICE_THRESHOLD = 0.5`).

## Procedure

```powershell
.\.venv\Scripts\python.exe verify_device.py ssim\saline-tank-2026-10-02
```

Exit code 0 on pass, 1 if any run fails to beat its control, 2 on a malformed series.
`--angle-limit` changes the pass threshold (default 10°, a third of the electrode sector).

### Step 1 — electronics, before any image metric

Image scores are blind to these. They are the majority of the checks.

| check | why |
|---|---|
| I2C scan: MCP4725 and ADS1115 present | sensors present |
| Shunt reads 97.9 Ω, matching the firmware constant | every resistance is scaled by this |
| Drive current in **all 12 excitation pairs** | `reconstruct_difference` applies **one scalar** to the whole measurement vector and cannot correct a per-pair error; unequal drive biases reconstruction toward the tank centre (ADR-0046) |
| Mux continuity C0–C11 | a dead channel reads as a healthy region |
| Reciprocity per run | catches sensor and wiring faults. Found a real V− wiring fault (ADR-0031) |

### Step 2 — empty tank

Capture a baseline, then capture again with no target. Score the second as if it were a
target. **It must not beat the detection.** This is the highest-value single check.

### Step 3 — known target at ≥3 opposite sectors

Reconstructing a healthy tank is the one thing that separates localisation from a
plausible-looking image. Opposite sectors catch a rotated or mirrored electrode map —
the D-01 failure, which produced good-looking images of a target in the wrong place.

### Step 4 — score the series

`verify_device.py` reports all three per run with controls, and a verdict per run:
`PASS`, `MARGINAL` (detected but angle over limit), `FAIL` (does not beat its empty tank).

## Result on the 2026-10-02 saline series

19 runs scored. **0 fail, 1 marginal.**

| | |
|---|---|
| Angular localization error | median **3.9°**, max **11.9°**, 17 of 18 within 10° |
| NCC beats its empty tank | **19 / 19** |
| Dice beats its empty tank | **19 / 19** |

The one exception is run `165444` at E2, **11.9°** — the run the series README already
identifies as drift-affected, and the electrode where every drift observation in that
afternoon appeared.

Two margins are much smaller than the rest and worth re-measuring if the tank is ever
set up again: `145332` at E7 has an NCC margin of 0.21 (an empty-tank control of 0.692
means that baseline already contained structure near E7 — contamination or drift), and
`174738` has a Dice margin of 0.16.

## Known gaps

- The electrode inset is unmodelled. The mesh puts electrodes on the domain boundary; the
  hardware has them ~30 mm inside a 128 mm bucket, which is 23% of the radius (ADR-0049).
- `NEAR_RADIUS_MM = 55.0` is inverted from the data, not measured. **One tape measure
  would close it**, and every mask radius depends on it.
- Depth sensitivity is untested.
- Specificity is untested: nothing shows the metrics do *not* fire on a non-anomaly.
- One pair run, `173951`, has no photograph of its setup. Its ground truth is partly
  inferred from its own result and it should not be cited as a confirmed localization.
